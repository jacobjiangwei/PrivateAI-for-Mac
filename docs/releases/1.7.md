# PrivateAI 1.7

## What's New

- A dedicated generation metrics section separates live token-rate estimates, first-output latency, first-answer time, provider-reported token totals, request size, Tool-schema size, and model load/prompt-evaluation time. Thinking contributes to live output metrics.
- The conversation transcript distinguishes user messages, raw model inputs, thinking, Tool calls, Tool results, intermediate outputs, and final answers. AI input JSON is indented for readability with one whole-message disclosure; copying preserves the original request body.
- Each user turn includes one compact snapshot of local date/time, time zone, locale, preferred languages, macOS version, and architecture. Tool rounds retain the same snapshot without repeated appends; the next user turn samples again. No device name, user name, serial number, or location is included.
- Streaming rendering keeps one WebView update in flight and sends only changed messages. Streaming deltas no longer trigger a synchronous database save or a separate disk log write for every chunk; terminal message-state updates still persist content.
- Location integration now declares the when-in-use purpose, distinguishes authorization timeout from coordinate timeout, supports cancellation, and retains request-scoped diagnostics from system delegate callbacks. These changes do not bypass macOS authorization or substitute an inferred location.
- Legacy privacy migration preserves the new raw Tool call/result records when the App restarts.

## Privacy and Compatibility

Raw requests, thinking, Tool arguments, and full Tool result text are stored in the local conversation database. They may include document text, paths, intermediate summaries, and encoded images. These diagnostic rows are excluded from future conversation history; operational logs remain metadata-only. Deleting a conversation deletes its diagnostic message rows. See the updated privacy policy for details.

Existing conversations remain readable. Raw requests from older runs cannot be reconstructed. Quit an older running build before launching the update, especially when using protected macOS services.

## Verification Boundaries

Signed App runs with a real Ollama model verified visible streaming, raw request rendering, local date/locale answers without Tool calls, Tool-result propagation, and native location answers against independently obtained system results. Tests also cover date rollover/DST, raw persistence, migration, metrics, rendering, and location authorization/cancellation state contracts.

Live token speed remains an estimate until Ollama reports completed-request token counts. Location availability still depends on authorization and system services. Full XCUITest automation was interrupted by macOS `CacheDeleteAppContainerCaches` terminating the UI runner; that check is not reported as passed. Signed App acceptance results are separate from this runner limitation.

- 独立展示生成速度、TTFT、首个正文时间、实际 token 数及输入大小，thinking 计入实时统计。
- 聊天记录展示原始模型输入、思考、工具调用和结果；JSON 简单缩进，只保留整条折叠，复制仍为原文。

- 减少逐 token 持久化和 WebView 渲染积压。
- 修正定位用途说明、授权与定位超时的区分、取消及回调诊断。
- 原始请求和工具结果是本地持久化会话数据，可能包含文档内容或图片编码；完整 XCUITest 受系统清理服务终止 runner 影响，未计为通过。
